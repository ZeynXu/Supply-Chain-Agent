# 客商分级与履约额度管理办法

## 一、目的

为进一步防范供应链业务中的客商履约风险，加强客商分级管理，健全风险管控机制，保障业务平稳运行，特制定本管理办法。本办法将作为智能工单处理系统在审批类工单场景中进行合规校验与风险提示的核心规则来源。

## 二、术语

本办法所称“客商履约额度”，系指在供应链业务中，与客商已签订采购订单未完成发货、或已签订销售订单未完成回款的金额上限。

## 三、客商风险分级标准

根据客商属性、交易行为及履约记录综合评定，将客商风险等级设定为五级，其中A级风险最小，E级风险最大。系统在工单审批环节，将依据此分级标准自动计算并提示当前客商的风险等级与对应的履约额度上限。

| 等级 | 画像描述 |
|:---|:---|
| **A级（优质客户）** | 企业型客户（Corporate/Home Office），合作记录良好，历史订单中延迟交货风险标记（Late_delivery_risk）出现比例极低，且从未出现“Shipping canceled”状态。订单利润贡献稳定，无异常纠纷记录。 |
| **B级（良好客户）** | 企业型客户或高价值个人消费者，合作记录总体正常，偶有“Late delivery”情况但沟通顺畅，无“Shipping canceled”记录。历史订单履约率保持在较高水平。 |
| **C级（一般客户）** | 以个人消费者（Consumer）为主，或合作历史较短的企业客户。存在一定比例的延迟交货记录，但未出现集中的履约异常。订单金额和利润贡献处于平均水平。 |
| **D级（关注客户）** | 近期出现多次“Late delivery”或曾出现“Shipping canceled”记录的客户。订单状态中“ON_HOLD”、“PAYMENT_REVIEW”或“SUSPECTED_FRAUD”出现频次较高，需重点关注。 |
| **E级（高风险客户）** | 频繁出现“Shipping canceled”状态，或订单状态长期处于“PENDING_PAYMENT”、“SUSPECTED_FRAUD”等异常状态。历史履约率低，延迟风险标记集中。订单利润贡献低或出现大额亏损订单。 |

## 四、分级客商履约额度

根据客商风险等级，结合历史订单金额及利润表现，设定差异化的履约额度管控上限。系统将在审批流程中自动校验当前客商的履约占用是否超出对应额度。

| 等级 | 履约额度区间 | 管控策略 |
|:---|:---|:---|
| **A级（优质客户）** | ＞50,000 | 额度充裕，可优先保障其订单履约资源；对于超额需求，系统提示后可进入快速审批通道。 |
| **B级（良好客户）** | 20,000 ~ 50,000 | 适用标准额度，作为稳定业务来源。超额时系统自动提示，需提交额度调整申请。 |
| **C级（一般客户）** | 5,000 ~ 20,000 | 额度适中，满足常规交易需求。超额时系统强制触发审批流程，建议补充履约保障措施。 |
| **D级（关注客户）** | 2,000 ~ 5,000 | 额度从紧，单笔大额订单需逐单审批。系统自动标记，建议采用预付款或分阶段付款方式。 |
| **E级（高风险客户）** | ＜2,000 | 额度严格限制，原则上不批准超额订单。新增订单需经特别审批，并强制要求预付款或保证金。 |

## 五、评估管理细则

### 1. 初始化评估与日常管控

（1）系统上线时，将根据历史订单数据对存量客商进行风险等级初始化评估。评估维度包括：客户类型（Customer Segment）、历史订单状态分布（Order Status）、延迟交货风险比例（Late_delivery_risk）、发货状态统计（Delivery Status）、平均订单利润（Order Profit Per Order）等。评估结果维护至系统客商信息中。

（2）新增客商首次交易时，系统根据其客户类型（Corporate/Home Office/Consumer）及首笔订单金额，给予初始风险等级（默认C级），待积累足够交易数据后动态调整。

（3）工单审批时，系统自动计算该客商当前未完成订单的总金额（即履约占用），与客商履约额度上限进行比对。若超出限额，系统生成风险提示并引导进入人工审批流程。如情况紧急，可转有权审批人处理。

### 2. 扩额申请

客商履约额度原则上应严格控制。若业务需要突破当前额度上限，需通过系统提交额度调整申请，经审批后生效。

（1）**临时额度调整**：适用于单笔或短期业务需求。系统将结合客商近期履约表现（如近30天延迟率、有无取消记录）进行综合评估，给出建议额度，经审批后生效。

（2）**固定额度跨级调整**：适用于客商交易规模发生根本性变化的场景。需结合客商累计销售额（Sales per customer）、累计订单利润、订单履约率等数据重新评估，经审批后调整其风险等级及对应额度。

### 3. 动态调整

系统在合同履约跟踪过程中，若检测到以下异常信号，将自动触发风险等级重评估：

- 订单状态出现“Shipping canceled”或“SUSPECTED_FRAUD”；
- 同一客商在短期内集中出现“Late delivery”（Late_delivery_risk=1）；
- 订单利润持续为负（Order Profit Per Order < 0），且无改善趋势；
- 订单长期处于“PENDING_PAYMENT”或“PAYMENT_REVIEW”状态超时。

经确认的异常将自动调降客商风险等级及对应履约额度，并通知相关业务人员。

### 4. 异常处置

（1）系统通过数据分析识别出客商交易行为或履约状态发生显著恶化时，将自动生成预警工单，提醒业务人员关注并核实。

（2）对于已确认的异常客商，系统将在审批环节自动拦截新增订单的自动通过，强制转人工审核，并提示优先跟进现有合同的履约进度。

（3）如客商发货或提货进度异常，系统将建议采取取消待执行订单、要求追加担保等措施，并将建议记录在工单处理报告中。

## 六、附则

1. 各等级客商的具体量化评分规则及额度阈值，将根据业务数据分布特征持续校准，由系统管理员定期维护更新。
2. 本办法中的金额单位为系统默认货币单位，可根据实际业务需要进行配置。
3. 本办法自发布之日起生效，后续将根据业务发展持续迭代优化。
